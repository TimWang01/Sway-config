# Reflect findings & workflow caveats — reference

Reference for future sessions. Compiled Sep 3, 2026 from a long session
covering the webcam privacy widget (SDD workflow), waybar styling, swaylock/
suspend debugging, zram tuning, and titlebar/border pixel work.

## Repeated workflows worth packaging (not yet applied)

### 1. PNG pixel-analysis decoder — re-derived 6+ times, no asset exists

The grim-screenshot → python decoder was rewritten from scratch in at least
six separate debugging sessions:

- Tab-bar visibility (hide_lone_tab, `--i3`)
- Titlebar color verification (Nord `client.*` slots)
- Lone-child titlebar regression
- smart_borders on/off
- Border thickness (4px) and focused/unfocused border colors

**Technique (reusable):** grim writes PNG colortype 2 (RGB 3bpp) **with
per-row filters 1/2/3/4** — a naive decode is wrong. The decoder must
unfilter sub/up/avg/paeth per row, then sample dominant colors per row.

**Known decoder bug found once:** the chunk walker skipped the 4-byte CRC
(`p += 8 + ln` needed `+4`). If re-deriving, include the CRC skip.

**Recommended form:** a root-level `px-rows.py` next to `validate-waybar.sh`
(repo keeps helper scripts at root). Not a skill — it is a tool.

### 2. Waybar restart + verify — 8+ occurrences, undocumented

```sh
pkill -x waybar || true; sleep 1; waybar >/tmp/waybar-restart.log 2>&1 & disown; sleep 2; pgrep -c -x waybar
```

Expect exactly 1 process. Used across gradient, privacy, DND, audio, webcam,
and gap-fix work. AGENTS.md documents `validate-waybar.sh` but not this cycle.

### 3. Sway live reload + verify

```sh
swaymsg reload
swaymsg -t get_config | jq -r .config | grep '<directive>'
```

`sway --validate -c` (in AGENTS.md) is static; the live reload + active-config
grep is the runtime verification used throughout.

## Caveats / pitfalls (repeated, costly)

### Bash tool hangs

- **Piping `waybar -l trace` through grep hangs the bash tool.** Orphaned
  long-running children (`audio.sh`, `dnd.sh` — `pactl subscribe` loops)
  inherit the stdout pipe and keep it open. Use `timeout N waybar -l trace
  >/tmp/x.log 2>&1` in one command, grep the log in a separate command.
- **`pkill -f "audio.sh"` hangs** because it matches the bash tool's own
  command line. Inspect with `ps aux | grep '[w]aybar/audio.sh'` instead.
- **Running `swayidle-restart.sh` in the foreground hangs** (exec blocks).
  Always: `nohup ~/.config/sway/scripts/swayidle-restart.sh >/dev/null 2>&1 & disown`.
- **Testing `audio.sh` by running it with the path in the same command hangs**
  (orphan-kill guard's `pgrep -f "waybar/audio.sh"` matches the tool cmdline).
  Test via extracted function only.

### Vision limitation

- **This model cannot read images.** The Read tool returns "Cannot read image
  (this model does not support image input)". Do not argue with the user about
  it; route screenshots to @observer with the full file path. The user may
  insist the model "has visual" — it does not; observer is the only path.

### Waybar CSS limits

- GTK3/Waybar CSS has **no `spacing` property** on box containers
  (`style.css:158:11 'spacing' is not a valid property name` — Waybar fails to
  start). Module gaps come from the GTK box's internal spacing; negative
  margins on adjacent modules are the only CSS lever.
- GTK3 does **not** support CSS custom properties (`--x`); use
  `@define-color name value;` + `@name`.

### Waybar privacy/webcam gap (unresolved as of Sep 3)

Both `#privacy` and `#custom-webcam` currently have `margin: 0 -2px 0 0` in
`config/waybar/style.css`. The visible gap between the two widgets was not
confirmed fixed before the topic was closed. Next step if revisited: bump to
`-4px` or capture a fresh screenshot for @observer.

## Design principles (already in AGENTS.md, re-confirmed)

- **No news is good news** — quiet by default; indicators only when a state
  is worth knowing.
- **Don't change the source code** — config and scripts only, no patches or
  custom builds of sway/waybar/foot/swaylock/dunst.

## Skipped candidates

- swayidle restart pattern — already a script; the nohup+disown invocation is

- Custom agent — no distinct lane need emerged; prompt rules suffice.
